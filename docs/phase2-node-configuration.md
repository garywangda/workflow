# 第二轮：节点配置与表单设计

基线：`e0004f0`，现有第一轮 workflow。开发分支：`feat/phase2-node-configuration`。

## 本次可操作的功能

- 完整保留原有 7 类 Node Toolbar、二级预设菜单、节点样式和画布布局。第二轮 15 项配置模型在右侧 Inspector 中按兼容节点类型选择；外部服务与事件配置不在本轮实现。
- 尚无保存文档的新流程默认带手动发起节点及固定启动表单；已有保存的空画布不自动填充。
- 通过原有方式放置原有节点。选中旧节点后在 Inspector 中选择兼容的第二轮配置模型；节点配置可编辑并自动保存。
- 可创建、编辑、预览和选用表单库中的指定版本。Form.io 前端设计器在独立同源 iframe 中运行，避免 Bootstrap 样式及拖拽事件影响主应用。
- 表单字段使用稳定的 fieldId，支持选择已有兼容字段或随表单创建字段。修改显示名称不修改 fieldId。表单引用采用版本快照，编辑共享表单不会修改其他节点已绑定的版本。
- 文本、数字、金额、日期、日期时间、选择、布尔、人员标识、附件及一层明细表控件。人员当前配置稳定 ID，附件正式存储需要后端。
- 节点级只读、可写、隐藏、必填配置应用于预览；只读/隐藏与必填矛盾会阻止保存。
- 人工办理、审批规则、限定退回目标、自然小时截止/提醒、站内通知、流程字段赋值、条件测试、等待时间、业务结束等配置。
- 并行和 Merge 继续使用原有 Toolbar 节点；Inspector 配置其配对关系，检查器检查两个以上工作分支到达该汇合点。
- 草稿允许不完整。检查器阻止缺少启动/结束、断路、任意循环、缺少表单绑定/人员、审批出口、并行未汇合及若干类型错误的设计发布；点击问题选择对应节点。
- 发布保存不可变设计快照，后续编辑留在草稿；版本号递增。

## 数据与运行边界

本仓库仍是浏览器端原型，没有服务器、数据库、人员目录、任务执行引擎或调度服务。
字段库目前是节点表单快照中的流程字段定义；“已有字段”不是读取任意数据库表。
草稿、表单和发布设计分别保存到 `workflow.document.*`、`workflow.forms.v1`、`workflow.versions.*`。
发布按钮发布的是设计版本，不会真的发送通知、启动任务或执行审批。运行时提交快照、权限执行、角色解析、提醒调度及在途版本固定属于后续执行闭环，界面记录的是相应设计规则。

当前条件编辑支持一个字段的比较、空值判断、匹配及默认路径与示例值测试；复杂嵌套 AND/OR、多条优先条件、完整模拟器仍需扩展。当前数据更新是一项固定值赋值，计算及跨节点输出引用编辑器仍需扩展。并行同时写同一字段的冲突检查尚需扩展。发布检查是编辑器基础校验，不能替代运行引擎的完整语义验证。

## Canvas 核心边界

`WorkflowCanvas.tsx` 未修改。Node Toolbar、节点创建工厂入口、连线 handlers、四个 Handles、吸附参数、节点拖动、视口、缩放和删除确认逻辑保持第一轮版本。

`phase2-canvas.test.tsx` 使用真实 React Flow 验证原有节点放置、既有连线保留，以及取消/确认删除行为。

## 验证方式

运行 `npm test`、`npm run typecheck`、`npm run lint`、`npm run build`、`npm run test:styles` 和 `git diff --check`。

浏览器验证：创建流程 → 编辑启动表单 → 拖入 Text Field → 修改标签 → 保存字段 → Preview → Design → Save form → 重新打开/选用已保存版本。

Form.io 仅采用前端库；未接入其服务器或托管平台。锁文件保留具体版本。前端库许可证随依赖分发；其可视化设计器部分高级编辑器可能按组件加载官方 CDN 资源，应在正式离线部署前完成资源本地化。
